## 文档数据结构

### 整体层次结构

```
Document (文档) - 顶层
├── topic_title: string                    # 文档标题/主题
├── doc_questions: Question[]              # 文档级问题（Q1, Q2, Q3...）
├── doc_hypotheses: Hypothesis[]           # 文档级假设（H1, H2, H3...）
└── story_units: StoryUnit[]              # 故事单元（小节）数组
    └── StoryUnit (U1, U2, U3...)
        ├── title: string                 # 小节标题
        ├── core_point: string            # 核心论点
        ├── card_ids: string[]            # 关联的卡片 ID 列表
        ├── question_id?: string          # 关联的问题 ID（可选）
        └── hypothesis_id?: string        # 关联的假设 ID（可选）
```

### 数据关系图

```
Document (文档)
│
├─ doc_questions: [Q1, Q2, Q3]           ← 文档级问题
│
├─ doc_hypotheses: [H1, H2, H3]          ← 文档级假设
│   └─ 每个 H 关联一个 Q (question_id)
│
└─ story_units: [U1, U2, U3]             ← 故事单元（小节）
    │
    ├─ U1
    │  ├─ title: "小节标题1"
    │  ├─ core_point: "核心论点1"
    │  ├─ card_ids: [card_1, card_2]      ← 引用 Card
    │  ├─ question_id: "Q1"              ← 关联 Question
    │  └─ hypothesis_id: "H1"           ← 关联 Hypothesis
    │
    ├─ U2
    │  ├─ title: "小节标题2"
    │  ├─ core_point: "核心论点2"
    │  ├─ card_ids: [card_3]
    │  ├─ question_id: "Q2"
    │  └─ hypothesis_id: "H2"
    │
    └─ U3
       └─ ...
```

## 文档的"分支结构"解释

### 什么是"分支结构"？

这里的"分支结构"指的是**文档的层次化组织方式**，不是 Git 分支，而是：

1. **Document（文档）** - 顶层容器
   - 一个文档代表一个研究主题
   - 例如："茅台销售体系分析"

2. **StoryUnit（故事单元）** - 文档的小节
   - 每个文档包含多个 StoryUnit
   - 每个 StoryUnit 是一个独立的小节
   - 例如：U1="茅台销售体系构成"，U2="经销商体系问题"

3. **Card（卡片）** - 底层数据
   - 每个 StoryUnit 引用多个 Card
   - Card 是实际的内容片段（摘要、要点等）

### 实际例子

以你的文档 "茅台销售体系分析" 为例：

```
Document: "茅台销售体系分析"
│
├─ Questions (3个问题)
│  ├─ Q1: "茅台的销售体系由哪些主要构成部分组成？"
│  ├─ Q2: "茅台销售体系中存在哪些主要问题？"
│  └─ Q3: "茅台采取了哪些措施来改善其销售体系？"
│
├─ Hypotheses (3个假设)
│  ├─ H1: "茅台的销售体系主要由经销商和自营渠道组成..."
│  ├─ H2: "茅台的经销商体系存在腐败、失控终端价格..."
│  └─ H3: "茅台加大了自营渠道的建设力度..."
│
└─ Story Units (3个小节)
   ├─ U1: "茅台销售体系构成及经销商主导地位"
   │  ├─ 关联 Q1, H1
   │  └─ 使用卡片: [card_1765019218165_dczaj8yp3, card_1764862629223_1b3143s66]
   │
   ├─ U2: "经销商体系存在的主要问题及其影响"
   │  ├─ 关联 Q2, H2
   │  └─ 使用卡片: [card_1765019218165_dczaj8yp3]
   │
   └─ U3: "自营渠道建设与销售体系格局稳定性"
      ├─ 关联 Q3, H3
      └─ 使用卡片: [card_1765019218165_dczaj8yp3]
```

### 为什么会有"奇怪的分支结构"？

可能的原因：

1. **StoryUnit 之间的关联关系复杂**
   - 多个 StoryUnit 可能引用相同的 Card
   - 例如：U1、U2、U3 都使用了 `card_1765019218165_dczaj8yp3`

2. **Question/Hypothesis 关联不完整**
   - 某些 Hypothesis 的 `question_id` 为 `null`
   - 某些 StoryUnit 的 `hypothesis_id` 为 `null`

3. **卡片引用重叠**
   - 同一个 Card 被多个 StoryUnit 使用
   - 可能导致内容重复或逻辑混乱

## 红色文档名的原因

### 可能的原因

1. **浏览器默认链接样式**
   - 如果文档名是可点击的链接，浏览器可能显示为红色（已访问链接）
   - 检查 CSS: `.document-item-title` 默认颜色是 `#2c3e50`（深蓝灰色）

2. **CSS 样式问题**
   - 可能某些文档有特殊的 CSS 类或状态
   - 检查是否有 `.doc-list-item.active` 或其他状态类

3. **浏览器缓存问题**
   - 旧的 CSS 样式被缓存
   - 尝试强制刷新（Ctrl+F5）

### 检查方法

1. **查看实际样式**:
   - 打开浏览器开发者工具（F12）
   - 检查红色文档名的元素
   - 查看应用的 CSS 样式

2. **检查代码**:
   - 位置: `reading-cards-backend/public/styles.css` 第 668-676 行
   - `.document-item-title` 的颜色是 `#2c3e50`（不是红色）

3. **可能的动态样式**:
   - 检查 `app.js` 中是否有动态添加的样式
   - 搜索 `color.*red` 或 `style.*color`

## 🔍 周末检查建议

### 1. 检查文档结构的一致性

```javascript
// 检查每个 StoryUnit 是否都有关联的 Card
doc.story_units.forEach(unit => {
  if (!unit.card_ids || unit.card_ids.length === 0) {
    console.warn(`单元 ${unit.unit_id} 没有关联的卡片`);
  }
});

// 检查 Hypothesis 是否都关联了 Question
doc.doc_hypotheses.forEach(h => {
  if (!h.question_id) {
    console.warn(`假设 ${h.id} 没有关联的问题`);
  }
});
```

### 2. 检查卡片引用

- 是否有 StoryUnit 引用了不存在的 Card？
- 是否有 Card 被多个 StoryUnit 重复使用？

### 3. 检查红色文档名

- 打开浏览器开发者工具
- 检查红色文档名的实际 CSS 样式
- 查看是否有动态添加的样式

### 4. Git 分支管理

- 初始化 Git 仓库（如果还没有）
- 创建开发分支和主分支
- 定期提交代码
